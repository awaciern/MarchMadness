# MarchMadness

Trains scikit-learn models on KenPom and BartTorvik efficiency stats to predict NCAA tournament brackets, scores historical results via leave-one-year-out cross-validation, and fills out first-round brackets for the current year before the tournament begins. Includes a full-featured web UI (`app.py`) for interactive model building, result exploration, Monte Carlo bracket simulation, group bracket analysis, and feature importance visualization.

---

## Data Pipeline

Scripts must be run in this order when setting up or updating a year:

```
1. brackets_api.py              — fetch bracket matchups/results from NCAA API
2. convert_kenpom_txt.py        — convert KenPom HTML snapshot to KenPomData CSV
3. convert_barttorvik_txt.py    — convert BartTorvik .txt export to BartTorvikData CSV
4. find_name_mismatch.py        — diagnose team name mismatches across CSVs
5. determine_winner.py          — fix WinningTeam / Win__1 columns from scores
6. reconcile_name_mismatch.py   — normalize team names so all CSVs agree
7. compile_combined_data.py     — join game/bracket data with KenPom + BartTorvik stats
8. predict_brackets.py          — train model, simulate brackets, score results
```

Optional pre-tournament steps for 2-week / hotness features:
```
   convert_barttorvik_txt.py --no-seeds   → Data/2WeekBartTorvikData/<YEAR>.csv
   compute_hotness.py                     → Data/HotnessBartTorvikData/<YEAR>.csv
```

## Data Layout

```
Data/
  BracketData/<YEAR>/Round<N>_<YEAR>.csv          — raw bracket matchups per round
  GameData/<YEAR>.csv                              — raw per-game results
  KenPomData/<YEAR>.csv                            — KenPom full-season stats (one row per team)
  BartTorvikData/<YEAR>.csv                        — BartTorvik full-season stats
  2WeekBartTorvikData/<YEAR>.csv                   — BartTorvik rolling 2-week snapshot
  HotnessBartTorvikData/<YEAR>.csv                 — hotness delta (2-week minus full-season)
  BracketCombinedData/<YEAR>/Round<N>_<YEAR>.csv   — bracket + KP + BT merged (generated)
  GameCombinedData/<YEAR>.csv                      — game + KP + BT merged (generated)
  GameCombinedData/All.csv                         — all years concatenated; primary training set
  SimulatedData<ID>/All.csv                        — synthetic training data (generated by generate_sim_data.py)
  TeamNames/team_names.csv                         — canonical team names and aliases
```

`GameCombinedData/All.csv` is the primary training set.  
`BracketCombinedData` is used at simulation time to look up round matchups and stats.

### Column naming convention

Combined CSVs use source-prefixed names so both stat sources coexist:

| Prefix | Source | Example |
|---|---|---|
| `KP__` | KenPom full-season | `KP__AdjEM__1`, `KP__AdjO__2` |
| `BT__` | BartTorvik full-season | `BT__Barthag__1`, `BT__EFG%__2` |
| `BT2W__` | BartTorvik 2-week rolling | `BT2W__AdjO__1` |
| `BTHOT__` | Hotness (2-week − season) | `BTHOT__AdjO__1` |

The `__1` / `__2` suffix identifies Team 1 / Team 2 in each matchup.

## Scripts

### `Python/predict_brackets.py`

Core training and evaluation script. Runs leave-one-year-out (LOYO) cross-validation and fills the current year's bracket if `--this-year` is supplied.

**Training procedure**

For each historical year, a model is trained on *all other years* (excluding the held-out year and any `--exclude-years`) then tested on the held-out year. This prevents data leakage. After the loop, a final full-data model is trained on all available years and saved as `model.pkl` for use in bracket simulation.

**LOYO metrics (primary)**

The model table and summary report the average train/test accuracy across all years in the cross-validation loop. These are the most meaningful generalization metrics. The final full-data model's stats (train acc on all data + traditional 67/33 split test acc) appear at the bottom of `summary.txt` for reference.

```bash
# Score all historical years with default features
python3 Python/predict_brackets.py --run-name LR_Default

# Predict current year's bracket
python3 Python/predict_brackets.py --run-name RF_2026 --this-year 2026

# Full example with many options
python3 Python/predict_brackets.py \
  --run-name SVC_AdjEM_NA_DF \
  --model svc \
  --model-params kernel=rbf C=8.0 \
  --features AdjEM KP_AdjO \
  --norm-all \
  --delta-feats \
  --exclude-years 2012 2013 2014 \
  --this-year 2026
```

#### Flags

| Flag | Description |
|---|---|
| `--run-name NAME` | *(required)* Folder name under `Predictions/` and display name in the UI |
| `--model KEY` | Model algorithm (default: `logistic_regression`) |
| `--model-params KEY=VAL ...` | Constructor kwargs for the model; auto-cast to int/float/bool/str |
| `--features BASE ...` | Space-separated feature base names (see Feature Groups below) |
| `--this-year YEAR` | Treat YEAR as current: train on all history, predict but don't score |
| `--final-four-pairings "i-j,k-l"` | How the 4 Elite Eight winners are paired for the Final Four (current year only; default `0-1,2-3`) |
| `--norm-years` | Z-score normalise each year independently before training |
| `--norm-all` | Z-score normalise across all years with a single global scaler |
| `--delta-feats` | Replace `__1`/`__2` pairs with a single `__delta` (team1 − team2); keeps categorical cols as separate pairs |
| `--calibrate` | Apply temperature scaling to win probabilities |
| `--calibrate-mode stretch\|nll` | How to fit temperature: `stretch` scales the most-confident prediction to `--calibrate-target`; `nll` minimises out-of-fold NLL (default: `stretch`) |
| `--calibrate-target P` | Target max probability for `stretch` mode (default: `0.97`) |
| `--calibrate-temperature T` | Override auto-fitted temperature with a fixed value |
| `--exclude-years YEAR ...` | Remove years from both training data and evaluation |
| `--sim-data IDENTIFIER` | Augment training with `Data/SimulatedData<IDENTIFIER>/All.csv` (test always uses real data only) |

> **Note:** Feature base names are sorted alphabetically before building the model to ensure reproducibility regardless of input order.

#### Feature Groups

| Group | Prefix | Feature names |
|---|---|---|
| Common (always `KP__`) | `KP__` | `WinPct` `Wins` `Losses` `AdjO` `Rk_AdjO` `AdjD` `Rk_AdjD` `AdjT` `Rk_AdjT` |
| KenPom-only | `KP__` | `AdjEM` `Rk_AdjEM` `Luck` `Rk_Luck` `SOS_AdjEM` `Rk_SOS_AdjEM` `SOS_AdjO` `Rk_SOS_AdjO` `SOS_AdjD` `Rk_SOS_AdjD` `NCSOS_AdjEM` `Rk_NCSOS_AdjEM` |
| BartTorvik-only | `BT__` | `Barthag` `Rk_Barthag` `EFG%` `EFGD%` `TOR` `TORD` `ORB` `DRB` `FTR` `FTRD` `2P%` `2P%D` `3P%` `3P%D` `3PR` `3PRD` `WAB` `Rk_WAB` `ConfWinPct` `ConfWins` `ConfLosses` |
| 2-week BartTorvik | `BT2W__` | `2W_AdjO` `2W_AdjD` `2W_Barthag` (and others; base names start with `2W_`) |
| Hotness delta | `BTHOT__` | `HOT_AdjO` `HOT_AdjD` `HOT_Barthag` (and others; base names start with `HOT_`) |
| Categorical opt-ins | varies | `Conf` `Seed` |

Default features: `WinPct AdjO AdjD SOS_AdjEM`

#### Supported models (`--model`)

| Key | Algorithm |
|---|---|
| `logistic_regression` *(default)* | Logistic Regression |
| `knn` | k-Nearest Neighbors |
| `svc` | Support Vector Machine (RBF, linear, poly) |
| `decision_tree` | Decision Tree |
| `random_forest` | Random Forest |
| `adaboost` | AdaBoost |
| `gpc` | Gaussian Process Classifier |
| `mlp` | Multi-Layer Perceptron |

**Output** (written to `Predictions/<run-name>/`):

| File | Contents |
|---|---|
| `<YEAR>.html` | Visual bracket with round-by-round predictions and correctness |
| `summary.txt` | LOYO-average train/test acc, per-year breakdown, bracket scores, full-data model reference |
| `model.pkl` | Serialized full-data model for Monte Carlo simulation |
| `model_info.json` | Metadata consumed by the web UI (features, params, LOYO accuracy, score) |

### `Python/generate_sim_data.py`

Generates synthetic training data to augment `GameCombinedData/All.csv`. Seven methods in two groups:

**Score-perturbation** (perturb game outcomes; features unchanged)

| Method | Description | Key flags |
|---|---|---|
| `noise` | Add independent Gaussian noise to both teams' scores | `--std` |
| `margin` | Perturb the point spread only (total score held fixed) | `--std` |
| `logistic` | Sample win/loss from Bradley-Terry probabilities; synthesise scores from KenPom AdjO/AdjT | `--score-std` |

**Feature-perturbation** (modify team statistics; win label inherited from source row)

| Method | Description | Key flags |
|---|---|---|
| `feature_noise` | Independent Gaussian noise on every numeric feature column | `--feat-noise-frac` |
| `correlated` | Multivariate Gaussian noise using Ledoit-Wolf regularised empirical covariance (related stats move together) | `--feat-noise-frac` |
| `smote` | k-NN SMOTE-style linear interpolation between nearest neighbours in PCA-compressed space | `--k-neighbors` `--pca-components` |
| `mixup` | Convex combinations of random row pairs with Beta(α,α) mixing weights | `--mixup-alpha` |

Output: `Data/SimulatedData<identifier>/All.csv`

```bash
# Feature noise, 10 copies per real row
python3 Python/generate_sim_data.py --method feature_noise --identifier FN10 --n 10

# Correlated MVN noise at 8% of column std
python3 Python/generate_sim_data.py --method correlated --identifier Corr8 --n 10 --feat-noise-frac 0.08

# SMOTE with 5 nearest neighbours
python3 Python/generate_sim_data.py --method smote --identifier SMOTE5 --n 5

# Mixup alpha=2
python3 Python/generate_sim_data.py --method mixup --identifier Mixup2 --n 10

# Score-perturbation (original methods)
python3 Python/generate_sim_data.py --method margin --identifier Margin8 --std 8 --n 15
python3 Python/generate_sim_data.py --method logistic --identifier BT20 --n 20
python3 Python/generate_sim_data.py --method noise --identifier Noise5 --std 5 --n 15
```

Common flags: `--seed INT` (default 42), `--dry-run` (print stats without writing), `--source PATH` (override input CSV), `--data-root PATH`.

Use the generated dataset with `predict_brackets.py --sim-data <identifier>`.

### `Python/simulate_bracket.py`

Monte Carlo bracket simulation using a saved `model.pkl`. Rather than always picking the favourite, each game is decided probabilistically using the model's win probability as the coin-flip weight. Running many iterations produces empirical advancement probabilities for every team.

```bash
python3 Python/simulate_bracket.py \
    --model Predictions/MyModel/model.pkl \
    --year 2026 \
    --num-iters 10000

python3 Python/simulate_bracket.py \
    --model Predictions/MyModel/model.pkl \
    --year 2026 --num-iters 5000 \
    --final-four-pairings "0-2,1-3" --seed 42
```

Output: `Simulations/<model-folder>/<year>_<N>iters.csv` and a matching `.html` table sorted by championship probability. Accessible through the Simulations tab in the web UI.

---

### `Python/compute_hotness.py`

Computes per-team "hotness" — the difference between the 2-week rolling BartTorvik stats and full-season stats. A positive value means a team is playing *better* recently than their season average.

```bash
python3 Python/compute_hotness.py              # all available years
python3 Python/compute_hotness.py --years 2026
```

Input: `Data/BartTorvikData/<YEAR>.csv` and `Data/2WeekBartTorvikData/<YEAR>.csv`  
Output: `Data/HotnessBartTorvikData/<YEAR>.csv`

### `Python/app.py` — Web UI

```bash
python3 Python/app.py
# Open http://localhost:5050
```

#### Train a model

The left-hand form exposes all `predict_brackets.py` options:

- **Model name** — sets the output folder name
- **Model type + parameters** — all 8 model types; optional `key=value` constructor overrides
- **Features** — click-to-toggle chip grid color-coded by source (blue = common/KP, purple = KP-only, pink = BT full-season, teal = BT 2-week, orange = hotness delta, green = metadata)
- **Normalisation** — off / per-year Z-score / global Z-score
- **Delta features** — combine `__1`/`__2` pairs into a single per-feature delta
- **Probability calibration** — temperature scaling (stretch or NLL mode) with adjustable target
- **Exclude years** — remove specific years from training and evaluation
- **Simulated data** — select a pre-generated `SimulatedData<ID>` dataset to augment training

Clicking **Run** launches `predict_brackets.py` in the background. A live log streams output line-by-line as it runs.

#### Results panel

After a run (or clicking any saved model row):
- **Summary** — per-year LOYO accuracy, bracket scores, round-by-round breakdown, and the full-data reference model accuracy
- **Year links** — click any year to view its HTML bracket; the current year is highlighted with a ★
- **Avg Train / Avg Test columns** — LOYO-average metrics (blank for older models that pre-date LOYO tracking)

#### Model table

Sortable table listing every folder in `Predictions/`. Columns: rank, avg bracket score, avg LOYO train acc, avg LOYO test acc, model type, normalization, features, params. Clicking a row loads its summary and brackets instantly.

#### Simulations tab

Run Monte Carlo simulations on any saved model directly from the UI. Select a model, year, number of iterations, and Final Four pairings, then view the advancement-probability table. Results persist in `Simulations/` and are listed per model.

#### Group Analysis tab

Upload multiple bracket JSON files (e.g. a group picks contest). For each bracket in the group, the UI scores it across user-defined game outcomes and shows each participant's current score, predicted champion, and round-by-round breakdown. Also shows simulation-based win probabilities for each bracket to win the group outright.

#### Feature Explorer tab

Visualizes which features are most predictive across historical years:
- **Win Correlation** — top features by correlation with the win outcome, broken down by tournament round
- **RF Importance** — feature importances from a Random Forest fitted on all data
- **Feature Correlation Matrix** — Pearson correlation heatmap between feature deltas (highlights redundant pairs)

Charts show ranked labels (`#1`, `#2`, …) for easy comparison.

### `Python/compile_combined_data.py`

Joins `BracketData` and `GameData` with all stat sources (`KenPomData`, `BartTorvikData`, `2WeekBartTorvikData`, `HotnessBartTorvikData`) and writes `BracketCombinedData` and `GameCombinedData`. BartTorvik columns use a left join so rows compile even when BT data is absent for a year.

```bash
python3 Python/compile_combined_data.py                    # all years, both types
python3 Python/compile_combined_data.py --year 2025        # single year
python3 Python/compile_combined_data.py --type bracket     # bracket only
python3 Python/compile_combined_data.py --type game        # game only
python3 Python/compile_combined_data.py --this-year 2026   # Round 1 bracket only (pre-tournament)
```

`--this-year` skips `GameData` (no games yet) and only compiles Round 1 of `BracketCombinedData`.

## Adding a New Year (Pre-Tournament)

1. Save KenPom HTML → `convert_kenpom_txt.py --no-seeds`
2. Paste BartTorvik full-season export → `convert_barttorvik_txt.py --no-seeds`
3. *(Optional)* Paste BartTorvik 2-week export → `convert_barttorvik_txt.py --no-seeds` into `2WeekBartTorvikData/`, then `compute_hotness.py`
4. Enter matchups in `BracketData/<YEAR>/Round1_<YEAR>.csv` (32 rows, scores = 0)
5. Run `reconcile_name_mismatch.py --year <YEAR>` — fix any reported mismatches in `team_names.csv`
6. Run `compile_combined_data.py --this-year <YEAR>`
7. Run `predict_brackets.py --run-name <NAME> --this-year <YEAR>` (or use the web UI)

## Adding a New Year (Post-Tournament)

1. Fetch bracket results: `brackets_api.py <YEAR>` (or enter manually)
2. Run `determine_winner.py --year <YEAR>`
3. Run `reconcile_name_mismatch.py --year <YEAR>`
4. Run `compile_combined_data.py --year <YEAR>`
5. Retrain any models (no `--this-year`; all years will be fully scored in the LOYO loop)
